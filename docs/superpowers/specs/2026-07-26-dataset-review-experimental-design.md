# Dataset Review — Experimental Design

Date: 2026-07-26
Status: pre-registered design, no runs yet
Vault entry point: `docs/obsidian/Project Pivot.md`

## Purpose

AMLK is now a review of HeSum as a training resource. `data_curation/` has already produced a curated
dataset; this document specifies how we establish that the curation was **justified** and that it
**helped**, in a way that survives the obvious objections.

It is written as a pre-registration. Metrics, tests, and directional predictions are fixed here, before
any result exists, so that the analysis cannot be steered by what the data turns out to say. Deviations
from this document must be recorded as deviations rather than silently adopted.

Training is owned externally. Section 7 defines that boundary.

## 2. Unified row labels

One artifact joining everything already on disk, keyed by `hesum_id`, covering all 10,000 rows.

```json
{
  "hesum_id": "1",
  "article_tokens": 3812,
  "headline_tokens": 18,
  "n_pipes": 0,
  "over_token_budget": false,
  "multi_pipe": false,
  "tail_boilerplate_removed": false,
  "source_label": "usable",
  "reached_model_curation": true,
  "headline_action": "kept",
  "headline_edit_type": null,
  "headline_lead_overlap": 0.31
}
```

Every field is derivable without new labeling. `over_token_budget` and `multi_pipe` come from the
10,000-id keep maps (`token_budget_upto_4000.json`, `headline_pipes_upto_1.json`) — note these are
**regenerated by `python -m data_curation.build_curated_dataset`, not committed**, so building this
artifact starts with a pipeline run. `source_label` comes from `source_filter_results.json` where present
and is `null` for the 3,514 rows that never reached the model;
`headline_action`/`headline_edit_type` from `headline_target_curation_results.json` plus the
`(original, replacement)` diff; `headline_lead_overlap` computed fresh.

**No new LLM labeling pass is required to build this.** That is the point — the deterministic filters
already defined clusters, and discarding membership was a bookkeeping choice, not a loss of information.
Both filters write complete boolean maps over all 10,000 ids rather than filtered row lists, which is what
makes the recovery a join.

### Headline edit sub-types

Assigned from the `(original, replacement)` string pair only, no article needed:

- `pipes_removed` — original had pipes, replacement does not
- `boilerplate_stripped` — replacement approximates the original minus a site label, credit, or category tag
- `truncation_repaired` — original ends mid-clause or is visibly cut
- `light_edit` — high token overlap, small local change
- `full_rewrite` — low token overlap with the original

The analytically important split is `full_rewrite` against everything else: a full rewrite means the
original carried little usable signal, the others mean it was salvageable.

## 3. Analysis strata

| Stratum | n | Derivation | Use |
|---------|---|-----------|-----|
| S0 `clean` | 2,785 | passed all filters, headline kept | reference group |
| S2 `multi_pipe_headline` | 2,412 | `n_pipes >= 2` | testable |
| S3 `multiple_independent_items` | 569 | source label | testable |
| S4 `headline_rewritten` | 3,069 | `headline_action == "rewritten"` | testable, sub-typed |
| S5 `other_unusable` | 63 | three small source labels collapsed | prevalence only |

Strata **overlap** deliberately: a row may be both a pipe digest and a roundup. Marginal tests therefore
double-count such rows and cannot attribute an effect, which is why the regression in 4.3 is the primary
analysis and uses separate binary indicators rather than one categorical variable.

S5's constituents (32 / 27 / 4 rows) cannot support any test. Report prevalence, exclude from statistics.

### Why there is no S1

`over_token_budget` (2,659 rows) is deliberately **not** a stratum. The filter is a hard cut at 4,000
tokens, so S0 lies entirely below the threshold and the over-budget group entirely above it: treatment and
confounder are the same variable and the groups share **no common support** in article length.

Consequences: caliper matching is impossible, since no clean row is length-comparable. A regression could
identify the effect only by extrapolating the length curve across the threshold, resting entirely on
assumed functional form. And any raw difference is fully explained by length alone.

`over_token_budget` is an arbitrary cut on a continuous covariate, not a defect class — nothing is wrong
with a 5,000-token article as such. Model length continuously over all 10,000 rows instead (4.4).

S2 survives because pipe count is not analogous: a three-segment digest is a qualitatively different
object from a single headline, not the same object further along a scale.

## 4. E1 — Was the diagnosis right?

Do the rows curation flagged actually have worse references?

### 4.1 Measurement

The rubric judge from `docs/obsidian/Reference Quality Rubric.md`, applied to
`(article, original headline)` for all 10,000 rows, returning four ordinal 1-to-5 sub-scores:
**faithfulness**, **single-focus**, **informativeness**, **cleanliness**.

Reference-free by construction — it reads the source rather than comparing two strings — which removes
the probe-model indirection an earlier draft of this design required, and with it a whole model's worth
of confound.

Metric hierarchy, fixed here:

- **Primary:** the four sub-scores
- **Secondary:** AlephBERT BERTScore F1 (`compute_bertscore` in `evaluation/evaluate.py`)
- **Appendix only:** Hebrew-normalized ROUGE, for comparability with HeSum Table 3, never carrying a claim

### 4.2 Hypotheses

- **H0:** each sub-score's distribution is independent of stratum.
- **H1:** at least one stratum differs.

Directional predictions, pre-registered so results can contradict them:

| Stratum | Predicted damage |
|---------|------------------|
| S2 `multi_pipe_headline` | single-focus and cleanliness down; faithfulness roughly intact |
| S3 `multiple_independent_items` | single-focus down; others near normal |
| S4 `headline_rewritten` | all four down, most in whichever dimension drove the rewrite |
| S5 `other_unusable` | informativeness down (prevalence only, untested) |

A defect damaging an unpredicted dimension is a result. Every defect damaging every dimension equally
means the rubric is not discriminating and must be revised before the results are used.

### 4.3 Tests

- **Mann-Whitney U**, each stratum against S0, one-sided in the predicted direction, **Holm-Bonferroni**
  corrected across the family. Report raw and adjusted p.
- **Cliff's delta** with bootstrap CI. **This carries the conclusion.** At n in the thousands
  Mann-Whitney returns p below 10^-10 for differences of no consequence, so significance is
  uninformative. Bands: negligible < 0.147, small < 0.33, medium < 0.474, else large.
- **Bootstrap 95% CI** on stratum medians, 10,000 resamples.
- **Ordinal logistic regression** — the primary analysis, not a supplement. Per sub-score:

  ```text
  score ~ multi_pipe + multiple_items + headline_rewritten
          + log(article_tokens) + headline_tokens
  ```

  Report each defect coefficient with CI. This is what separates overlapping strata and holds length fixed.

**No Kruskal-Wallis omnibus.** It assumes independent groups, our strata are not disjoint, and at this n
it would reject regardless. The regression does the job properly.

Scores are ordinal, so: no means, no OLS, no box plots. Distributions and rank statistics only.

### 4.4 Length and lead bias

Over all 10,000 rows including those the filters removed:

- Each sub-score against `log(article_tokens)`, binned medians with CI
- `headline_lead_overlap` against `log(article_tokens)`
- Mark the 4,000-token threshold; a *continuous* trend with no discontinuity at the cut is the evidence
  that the filter boundary is arbitrary

This replaces the Qwen-era three-variant training probe and is strictly more informative: every row
contributes, no extra training is needed, and it separates whether *references* are lead-aligned (a
dataset property) from whether a *model* relies on the lead (a model property, from section 7).

## 5. E2 — Was the repair right, and by how much?

Restricted to the **3,069 rewritten rows**. On the 2,785 kept rows the two headlines are the same string
and the comparison is vacuous.

Judge scores the curated headline on the same four dimensions. Compare paired per-row scores with
**Wilcoxon signed-rank** per dimension, broken out by `headline_edit_type`.

- **H0:** median paired difference is zero.
- **Prediction:** positive on the dimension that drove each edit type — cleanliness for
  `boilerplate_stripped`, single-focus for `pipes_removed`, all four for `full_rewrite`.

Gives magnitude and mechanism. **Known weakness:** ceiling compression — if both headlines score 4, a real
preference is invisible. E3 covers that blind spot, which is why both exist.

Also report the share of rows where a score **decreased**. Curation degrading references is a possibility
worth catching rather than averaging away.

## 6. E3 — Was the repair right, as a forced choice?

Same population, sampled to ~1,000 rows (±3% CI on the win rate, more precision than the claim needs).

### 6.1 Protocol

Judge sees the article and both headlines in **randomized order**, returns better / better / tie plus a
one-sentence justification. Never told which is original.

Forced choice detects consistent small preferences that graded scores compress away, and randomized order
makes it the more adversarial test of the shared-LLM-style confound.

- **H0:** win rate is 50% after null calibration.

### 6.2 Bias controls

These are what make the number credible rather than merely asserted.

- **Position bias:** run a subsample in both orders; report the flip rate. A high flip rate means the
  judge is reading position, not content.
- **Null calibration:** feed the judge a control where both options are effectively the same headline and
  measure how often it still declares a winner. That is the instrument's bias floor.
- **Placebo population:** the 2,785 kept rows, where the curator judged the original fine as-is. A
  head-to-head there should land near 50%; systematic deviation is measuring the judge and gets subtracted.
- **Family separation:** the judge must not be from `gpt-5.6-luna`'s family, nor from the training base
  model's. Otherwise a preference for curated references could be a preference for its own idiom.

### 6.3 Human validation

About 150 rows, annotated independently and blind by both team members with the same rubric, so one round
validates E1's instrument and E3's judge together.

Report per dimension: **Cohen's kappa** human-human, and judge-human agreement. Human-human matters as
much as judge-human — if two annotators cannot agree on single-focus, the dimension is underspecified and
the judge's confidence on it is spurious.

Interface: `evaluation/viewer/app.py`, which already renders RTL Hebrew side by side.

Also required, before any full run: **test-retest**, the judge twice at nonzero temperature over 300 rows,
quadratically weighted kappa per dimension.

### 6.4 If E2 and E3 disagree

Curated scoring higher on the rubric while the head-to-head sits near chance would mean the improvement is
real by rubric but imperceptible in direct comparison. That is a finding to report, not a failure to
reconcile. State it plainly rather than choosing whichever result is more favourable.

## 7. E4 — Did the intervention pay off?

Training is external. Full interface in `docs/obsidian/Training Handoff Contract.md`; the essentials:

**We produce the split.** 800 to 1,000 test rows, carved before any training, ids only, every test row
carrying both its original and curated reference, no test row in any arm's train or validation set.
Arms trained on independently drawn splits cannot be compared, and nothing downstream recovers from that.

**Arms.** A = raw HeSum subsampled to exactly B's size; B = curated; optional C = raw full 10,000.
**Size-matching A to B is non-negotiable** — otherwise data quality is confounded with data quantity.
Identical hyperparameters, base model, and decode config across arms.

**We require back** prediction files over the frozen split (preferred, since it means we never load a
model — `evaluation/infer.py` is remote-GPU-only and this machine has 8 GB) or checkpoints, plus a
manifest recording base model, hyperparameters, decode settings, subsample seed, and an explicit
`deviations` list.

**We run:** the same four-dimension rubric judge, so model outputs and dataset references sit on one axis;
BERTScore against both reference versions plus appendix ROUGE; blind pairwise between arms under E3's
bias controls; per-stratum readout; and lead-overlap distribution per arm.

**Pre-registered non-claims.** Arm A scoring higher against original references, and arm B against curated
references, are tautological — each arm matches the reference style it trained on. Neither is evidence.
The claim rests entirely on the reference-free rubric scores and the blind pairwise.

**Graceful degradation**, fixed now so the conclusion cannot stretch to fit what arrives:

- A and B → full causal claim available
- B only → nothing concluded about curation; deliverable falls back to the E1-E3 audit, which stands alone
- B and C only → confounded by training-set size; must be reported as confounded, not as a quality effect
- Arms on different splits → not recoverable; comparison abandoned

## 9. Compute placement

- **API and CPU:** the rubric judge for E1-E3, all statistics, all figure rendering. The bulk of the work.
- **Databricks GPU, worth it:** batch AlephBERT BERTScore (~20,000 scorings), and embedding work if a
  topic-stratified figure is wanted.
- **Never local:** any model load. `AGENTS.md` records that this machine freezes; `evaluation/infer.py` is
  remote-GPU-only.

## 10. Execution order

The judge dominates cost and wall-clock, so sequence to fail cheap:

1. Build the unified row-label artifact (section 2). Pure joins, no API.
2. F1 and F2 from existing artifacts. No API spend.
3. Draft the rubric's Hebrew anchors; both team members review. Anchors drawn from rows excluded from analysis.
4. **Pilot the rubric on a few hundred rows.** Check test-retest and that distributions are not
   degenerate. Revise here — this is the last cheap moment.
5. Full E1 judge pass over 10,000 rows → F3, F4, F5.
6. E2 and E3 over the rewritten rows → F6, F7.
7. Human validation round, parallel with 5 → F9.
8. E4 once arms arrive → F8.

Steps 1 to 4 have no dependency on the training owner and should not wait on them.

## 11. Threats to validity

To be carried into the paper, not buried:

- **LLM-written references.** Curated headlines came from `gpt-5.6-luna`. Mitigated by family separation
  and by the reference-free rubric, not eliminated.
- **Judge self-preference**, quantified as the null-calibration bias floor rather than assumed absent.
- **Judge reliability**, quantified by test-retest and human agreement. Any dimension with poor agreement
  must be reported as weak evidence.
- **Single-pass source labels.** The six categories in `source_filter_results.json` are one pass from one
  model with no re-label. `unusable_other = 0` is evidence of exhaustiveness but not of accuracy.
- **Stratum overlap**, handled by the regression but still limiting marginal interpretation.
- **Multiple comparisons**, handled by Holm, but the number of dimension-by-stratum tests is large and
  effect sizes should be read before p-values throughout.
- **Distribution shift, not just quality.** Filtering to 5,854 rows changes what the corpus is *about* —
  shorter articles, fewer roundups — and not only how clean it is. A curated-data win may partly reflect
  an easier task distribution.
- **The drops are untested.** Nothing here isolates whether removing 632 unusable and 3,514 filtered rows
  was correct. Would need a fourth training arm.
- **Human validation is small.** 150 rows, two annotators, both of whom designed the rubric. Not
  independent in the way a hired annotator would be; state this.
- **Contract deviations** in training must be reported. An unknown deviation invalidates E4.

## 12. Out of scope

Training runs and hyperparameter search (external). Re-labeling the source axis. Any new curation pass on
the dataset. A fourth training arm isolating the filter effect. Human annotation beyond 150 rows.
