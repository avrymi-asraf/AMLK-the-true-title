# Curation Roadmap

This roadmap describes the current `data_curation` pipeline from the raw HeSum download to the final cleaned headline-generation dataset. The goal is to preserve each source article with a stable string id, remove records that are not useful training examples, and produce a final dataset where every row is a clean pair of source text and headline.

The pipeline has three broad parts:

- Data download creates the raw local copy of HeSum.
- Pre-model cleanup applies deterministic filters and text cleanup.
- Model curation uses batch API decisions to remove unusable sources and repair noisy headline targets.

The final artifact is:

```text
data_curation/artifacts/final_clean_hesum.json
```

Each final record looks like:

```json
{
  "hesum_id": "1",
  "text": "...",
  "headline": "..."
}
```

The token-budget and headline-pipe filters are independent deterministic filters. Both read the tail-trimmed artifact, and their boolean keep maps are combined only when building the source-filter input.

Only the model-curation result artifacts need to be supplied with the project. All download and deterministic cleanup artifacts are regenerated by the pipeline.

## 1. Raw HeSum Download

The goal of this step is to create the local raw dataset artifact with only the fields needed for curation. We do this first so every later step works from one stable file instead of depending directly on the external dataset.

Input file:

```text
HuggingFace dataset: biunlp/HeSum
```

Output file:

```text
data_curation/artifacts/raw_hesum.json
```

Expected output size:

```text
10,000 records
```

Output shape:

```json
[
  {
    "id": "1",
    "text": "...",
    "headline": "..."
  }
]
```

`id` is a string id assigned during download, `text` is the article text, and `headline` is the original HeSum summary treated as the headline target.

## 2. Tail Boilerplate Trimming

The goal of this step is to remove repeated scraped boilerplate that appears at the end of article texts. We do this because repeated non-article tails teach the model irrelevant patterns and inflate the source text with content that should not affect headline generation.

Input file:

```text
data_curation/artifacts/raw_hesum.json
```

Internal output file:

```text
data_curation/pre_model_cleanup/tail_boilerplate_trimming/outputs/tail_boilerplate_candidates.json
```

Public output file:

```text
data_curation/artifacts/tail_boilerplate_removed.json
```

Expected output size:

```text
10,000 records
722 records had tail boilerplate removed
```

Internal candidate shape:

```json
[
  {
    "tail": "...",
    "count": 2,
    "length": 7,
    "ids": ["123", "456"]
  }
]
```

Public output shape:

```json
[
  {
    "id": "1",
    "text": "...",
    "headline": "...",
    "tail_boilerplate_removed": false
  }
]
```

## 3. DictaLM Token-Budget Filtering

The goal of this step is to mark records that fit the configured total token budget. We do this before API curation so later model-processing stages receive examples that fit the intended context limit.

Input file:

```text
data_curation/artifacts/tail_boilerplate_removed.json
```

Internal output file:

```text
data_curation/pre_model_cleanup/dictalm_token_budget_filtering/outputs/dictalm_token_counts.json
```

Public output file:

```text
data_curation/artifacts/token_budget_upto_4000.json
```

Expected output size:

```text
10,000 ids
7,341 kept
2,659 removed
```

Internal token-count shape:

```json
{
  "1": 3812,
  "2": 527
}
```

Public filter shape:

```json
{
  "1": true,
  "2": false
}
```

The boolean value means whether the record should be kept by this filter.

## 4. Multi-Pipe Headline Filtering

The goal of this step is to mark records whose original headline contains too many pipe characters. We do this because multi-pipe headlines are often bundles of several headline fragments, labels, or unrelated targets rather than one clean headline.

Input file:

```text
data_curation/artifacts/tail_boilerplate_removed.json
```

Output file:

```text
data_curation/artifacts/headline_pipes_upto_1.json
```

Expected output size:

```text
10,000 ids
7,588 kept
2,412 removed
```

Output shape:

```json
{
  "1": true,
  "2": false
}
```

The boolean value means whether the record should be kept by this filter.

## 5. Source-Filter Input Assembly

The goal of this step is to combine the deterministic pre-model filters into the input for model curation. We do this after the independent filters are complete so the API only sees records that pass the token-budget and headline-pipe checks.

Input files:

```text
data_curation/artifacts/tail_boilerplate_removed.json
data_curation/artifacts/token_budget_upto_4000.json
data_curation/artifacts/headline_pipes_upto_1.json
```

Output file:

```text
data_curation/artifacts/source_filter_input.json
```

Expected output size:

```text
6,486 records
```

Output shape:

```json
[
  {
    "id": "1",
    "text": "...",
    "headline": "..."
  }
]
```

This file is the first model-curation input and contains only records that passed every pre-model keep/remove map.

## 6. Source Filtering

The goal of this step is to label whether each source text is usable for headline-generation training. We do this because some articles are digests, fragments, too thin, or dependent on missing outside content even after deterministic cleanup.

Input file:

```text
data_curation/artifacts/source_filter_input.json
```

Internal output files:

```text
data_curation/model_curation/source_filter/outputs/filter_results.json
data_curation/model_curation/source_filter/outputs/filter_errors.jsonl
```

Public output file:

```text
data_curation/artifacts/source_filter_results.json
```

Supplied output size:

```text
6,486 results
5,854 usable
632 unusable
```

Label counts:

```text
usable                                      5,854
unusable_multiple_independent_items           569
unusable_insufficient_substantive_content      32
unusable_substantive_content_not_in_text       27
unusable_damaged_or_fragmentary_text            4
unusable_other                                  0
```

Output shape:

```json
[
  {
    "id": "1",
    "filter_label": "usable"
  }
]
```

The public artifact is written only when all source-filter input records have either a successful result or a recorded failure.

## 7. Headline Target Curation

The goal of this step is to decide whether each usable record can keep its original headline or needs a replacement headline. We do this because many source texts are usable while their original headline targets contain boilerplate, site labels, broken punctuation, duplicated text, or pipe-separated fragments.

Input files:

```text
data_curation/artifacts/source_filter_input.json
data_curation/artifacts/source_filter_results.json
```

Internal output files:

```text
data_curation/model_curation/headline_target_curation/outputs/refine_results.json
data_curation/model_curation/headline_target_curation/outputs/refine_errors.jsonl
```

Public output file:

```text
data_curation/artifacts/headline_target_curation_results.json
```

Supplied output size:

```text
5,854 results
2,785 original headlines kept
3,069 replacement headlines created
```

Output shape:

```json
[
  {
    "id": "1",
    "replacement_headline": null
  },
  {
    "id": "2",
    "replacement_headline": "..."
  }
]
```

`replacement_headline` is `null` when the original headline should be kept, and a string when the final dataset should use the curated replacement.

## 8. Final Dataset Assembly

The goal of this step is to materialize the dataset that will be used by the next model-processing section. We do this last so the final file contains only usable source texts with the correct final headline target already selected.

Input files:

```text
data_curation/artifacts/source_filter_input.json
data_curation/artifacts/source_filter_results.json
data_curation/artifacts/headline_target_curation_results.json
```

Output file:

```text
data_curation/artifacts/final_clean_hesum.json
```

Expected output size:

```text
5,854 records
```

Output shape:

```json
[
  {
    "hesum_id": "1",
    "text": "...",
    "headline": "..."
  }
]
```

The `hesum_id` field preserves the original string id from the curated HeSum record. The `headline` field is the original headline when no replacement was needed, otherwise it is the curated replacement headline.

data_curation/artifacts/source_filter_input.json
